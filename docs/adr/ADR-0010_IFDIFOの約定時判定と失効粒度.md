# ADR-0010: IFD/IFO の子の向きは約定時に最終判定し、不正時は IFD=子のみ失効 / IFO=OCOごと失効

- **ステータス**: 採用
- **日付**: 2026-06-28
- **関連**: 指示書「決済注文 C1 IFD」「決済注文 C2 IFO」/ ADR-0007・0008・0009

## 背景（なぜ判断が必要だったか）
IFD/IFO(新規＋決済の合成注文)では、子(決済レッグ)の価格を発注時に入力するが、
親(新規注文)が約定するまでに相場が動き、約定時には子のTP/SLの向きが成立不能になっている場合がある。
「いつの価格で向きを判定するか」「不正だったときにどうするか」を決める必要があった。

## 決定（何を選んだか）
1. **二段構えの検証**: 発注時は軽い妥当性チェックのみ(数量・価格・ペア)。
   子のTP/SLの**向きの最終判定は、親が約定した時点(建玉生成時)の価格**で行う。
2. **不正時は新規約定を成立させ、子を失効**(ロールバックしない):
   - **IFD**(子が1本): 不正なら**子のみ EXPIRED**。建玉は保持され、ユーザーは決済注文を出し直せる。
   - **IFO**(子がOCO 2本): **片方でも不正なら OCO ごと失効(両方 EXPIRED)**。
3. 親が約定前に取り消された場合は、子も CANCELLED(建玉が無いので決済レッグも消す)。

## 理由（なぜそれを選んだか）
- 発注時だけの検証では約定時のズレを拾えず、約定時だけの検証では明らかな入力ミスのフィードバックが遅い。二段構えが両立解。
- 新規約定は市場で成立した事実であり、後から取り消す(ロールバック)のは挙動として不自然で実装も複雑。
- IFDとIFOで失効の粒度が異なるのは、**「OCOはセットとして意味を持つ」**(ADR-0009)という思想の一貫のため。
  IFOで片方だけバインドすると中途半端な単独TP/SLが残り、OCOの意図(利確と損切りのペア)が壊れる。

## 検討した代替案
- **発注時の価格で厳密検証** — 約定までに相場が動くため、正しく検証できない。
- **不正なら新規約定ごとロールバック** — 約定済みの事実を取り消すことになり不自然・複雑。
- **IFOでも正当な方だけバインド** — C-1と対称でユーザーに親切な面はあるが、OCOのセット思想と矛盾するため不採用。

## 結果（トレードオフ・影響）
- 「建玉は持てたが決済レッグは付かなかった」という結果が起こりうる(EXPIREDで可視化、出し直しで回復可能)。
- IFD(子のみ失効)とIFO(OCOごと失効)の**非対称**は仕様であり、バグではない。本ADRが根拠。
- バインド後の子は段階A/Bのライフサイクルにそのま合流する(新規ロジックを作らない)。

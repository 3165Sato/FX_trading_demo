# ADR-0012: UIを3画面（見る/撃つ/振り返る）に分離し、「表は情報表示・操作は詳細パネル」を原則とする

- **ステータス**: 採用
- **日付**: 2026-06-28
- **関連**: 指示書「UI再構成 C31(1/2・3)」/ DESIGN.md(C-31改訂版) / ワイヤーフレーム v2

## 背景（なぜ判断が必要だったか）
機能追加(指値・逆指値、TP/SL、OCO、IFD/IFO、資産曲線…)により2画面(Monitor/Trading)のUIが複雑化した。
特に注文パネル(5種類の注文タイプが同居)と PositionsTable(行に情報と操作ボタンが渋滞)が限界に達し、
情報設計の見直しが必要になった。

## 決定（何を選んだか）
1. **3画面分離**: 役割を「見る / 撃つ / 振り返る」で分ける。
   - **Monitor**(見る): 市場と口座の観測(レート・チャート・スプレッド・ニュース・アラート・資産曲線)。
   - **Trading**(撃つ): 今この瞬間の判断に必要なものだけ(発注・建玉・PENDING待機注文・証拠金)。履歴系は置かない。
   - **History**(振り返る): 約定履歴・注文履歴(全状態)・損益サマリ・将来枠(期間損益・入出金)。
2. **注文パネルは2モードタブ**: シンプル(成行/指値/逆指値)と複合(IFD/IFOのステップ入力)。
3. **「表は情報表示・操作は詳細パネルへ」原則**: PositionsTable の行は情報+TP/SL/OCO有無バッジに徹し、
   行選択で開く建玉詳細パネルに操作(個別決済/TP/SL/OCO設定/取消/スワップ振替)を集約する。
4. 待機注文パネルは**PENDINGのみ**表示(終了済はHistoryへ)。

## 理由（なぜそれを選んだか）
- 「見る/撃つ/振り返る」はユーザーの行動モードそのものであり、モードごとに必要な情報が異なる。
  Tradingから履歴を追い出すことで、執行時の認知負荷を下げる。
- 複合注文(IFD/IFO)は入力が構造的に多く、フラットに並べると迷子になる。ステップ入力が適切。
- 行に操作を詰めると、列数の増加とともに可読性・誤操作リスクが悪化する。
  「表=読む、詳細=操作する」の分離は、今後の一覧系UI全般に適用できる原則になる。

## 検討した代替案
- **2画面のまま再構成** — 履歴系の置き場が確保できず、Tradingの過密が解消しない。
- **5種別フラットのまま見た目だけ整理** — 根本の情報量は減らず、IFO(親+OCO)の入力が破綻する。
- **行に操作ボタンを残す** — 機能が増えるたびに列が増える構造的問題が解決しない。

## 結果（トレードオフ・影響）
- 画面遷移が1回増える操作もある(履歴確認はHistoryタブへ)が、各画面の密度と明瞭さを優先した。
- 移設は「History に出た → Trading から消す」の順で行い、常にどちらかで見られる状態を保った(段階実装)。
- DESIGN.md を3画面構成に改訂(トークンは不変)。「表は情報・操作は詳細」を DESIGN.md のコンポーネント方針に明文化。
- History の将来枠(期間損益 C-12・入出金 C-11)を先に確保し、後続実装でレイアウトを作り直さない。

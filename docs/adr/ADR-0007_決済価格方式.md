# ADR-0007: 決済注文の価格方式（利確=指定価格 / 損切り=スリッページ許容）

- **ステータス**: 採用
- **日付**: 2026-06-28
- **関連**: 設計「決済注文 TP/SL→OCO→IFD/IFO 全体像」/ 指示書「決済注文 A 単独TPSL」/ ADR-0001

## 背景（なぜ判断が必要だったか）
決済注文(TP/SL)を「指値価格で決済(よりリアル)」とする方針を採ったが、利確(指値)と損切り(逆指値)では価格保証の性格が異なる。損切りを指定価格に固定すると、急変・窓開け時に現実にはあり得ない価格で約定してしまう。

## 決定（何を選んだか）
- **利確(TP / 決済指値)**: 指定価格で約定する(指定価格に到達して約定するため自然)。
- **損切り(SL / 決済逆指値)**: 指定価格をトリガーに、**現在の決済側価格で約定(スリッページ許容)**。
- トリガー判定は決済側価格で行う: LONG決済=Bid / SHORT決済=Ask。
- **許容スリッページ幅の指定は本系列(TP/SL→OCO→IFD/IFO)では実装しない**(幅指定なし・無制限許容)。

## 理由（なぜそれを選んだか）
- 損切りは不利な側のトリガーであり、指定価格での約定保証がないのが現実。リアルさを重視。
- 利確は有利な側で待つ注文なので、指定価格約定が自然で分かりやすい。
- スリッページ幅の指定は、ストリーミング注文など別系列で扱う方が概念的に整理される(将来導入)。

## 検討した代替案
- **両方とも指定価格** — 学習用には分かりやすいが、損切りが窓開けで非現実的な価格になる。
- **損切りにも許容スリッページ幅を指定(0〜10pips等)** — 一度検討したが、本系列では複雑化を避け見送り。
  幅指定は将来のストリーミング注文の論点とする。

## 結果（トレードオフ・影響）
- 損切りはトリガー到達時の現在値でそのまま約定する(約定を許容幅で制限しない)。
- 発注時に価格の向きを検証(LONG: TPはBidより上/SLはBidより下、SHORT: TPはAskより下/SLはAskより上)。
- スリッページ幅指定を導入する際は、別系列(ストリーミング注文)で新規に設計する。

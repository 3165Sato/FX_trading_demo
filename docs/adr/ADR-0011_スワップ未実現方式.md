# ADR-0011: スワップは未実現として建玉に積み、決済時に実現する（Equityの分子にのみ反映）

- **ステータス**: 採用
- **日付**: 2026-06-28
- **関連**: 指示書「スワップ損益 C07」「スワップ振替 C08」/ ADR-0001(個別建玉)・ADR-0004(レートFIXED)

## 背景（なぜ判断が必要だったか）
スワップ損益(保有期間に応じた金利差損益)を導入するにあたり、
付与したスワップを「即時に実現損益として残高へ足す」か「未実現として建玉に積み、決済時に実現する」かで、
損益の見え方・後続機能(振替)・Equityの構成が変わる。

## 決定（何を選んだか）
1. **未実現方式**: 各建玉に累計未実現スワップ(accruedSwap)を持ち、ロールオーバーごとに加算。
   **決済時(個別決済・ロスカット全決済とも)に実現して残高へ**加算し、建玉と共にクリアする。
2. **Equity への反映**: Equity ＝ 残高 ＋ 含み損益 ＋ 未実現スワップ合計。
   **必要証拠金(分母)は変更しない**(スワップは分子にのみ効く)。
3. 付与は**日次自動＋手動発火の併用**(デモは実時間で進むため、確認用の手動発火が必須)。
   レートは設定値(ペア別・売買別・符号付き、学習用の任意設定)。
4. **スワップ振替(C-08)**: 建玉を維持したまま未実現→実現へ移す第二の実現経路。
   振替の前後で **Equity・維持率は不変**(内訳の移動のみ)。マイナスも振替可。全額のみ。

## 理由（なぜそれを選んだか）
- 実際のFXは未実現方式(建玉を閉じるまでスワップは確定せず、途中振替も可能)が主流。リアルさ重視の方針と整合。
- 未実現方式でないと、スワップ振替(C-08)という実務機能が概念として成立しない。
- 「振替は損益を生まない、確定させるだけ」(Equity不変)という学習ポイントが数字で見える。
- 分母(必要証拠金)を変えないことで、1bの証拠金計算への影響を加算項1つに限定できる。

## 検討した代替案
- **即時実現方式**(付与のたび残高へ) — シンプルだが、振替の概念が消え、実現/未実現の境界を学べない。
- **金利からの動的算出** — 学習デモには過剰。固定レート(設定値)で「受け取り/支払いが分かれる」表現は足りる。
- **営業日ルール(3倍デー等)** — 将来拡張とし、日数は当面常に1。

## 結果（トレードオフ・影響）
- 建玉に accruedSwap が追加され、決済経路(個別決済・ロスカット)に実現処理が入る。
  振替済み建玉を決済した場合は実現スワップ0(二重実現しない)。
- 両建てでは各建玉に符号付きで付与され、受け取りと支払いが相殺気味になる(個別建玉モデルで自然に表現)。
- 資産曲線(F-18)にロールオーバーの階段が現れ、付与の検証が視覚的にできる。
- 将来: スワップ狙いの長期建玉の保護フラグ(C-09)は、NETTING(C-21)導入時にセットで設計する。

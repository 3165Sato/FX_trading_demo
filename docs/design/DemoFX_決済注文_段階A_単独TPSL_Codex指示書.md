# DemoFX 機能指示書: 決済注文 段階A（単独 TP/SL・指値価格決済・建玉失効連動）

## 1. 準拠
- 実装ルールは **CODEX.md** に従う(BigDecimal/HALF_UP、DTO返却、独立スケジュール、口座ロックで直列化、
  既存を壊さない・小ステップ、NEXT_PUBLIC_API_BASE_URL、logs非Git、着手前に既存を調査・報告)。
- UIは **DESIGN.md** に従う(PositionsTable、待機注文/予約一覧、状態の色分け)。
- 設計の正: **「決済注文 TP/SL → OCO → IFD/IFO 設計全体像」**(本書は段階A)。
- 前提機能: 個別建玉(1a: 建玉ID・個別決済)、評価損益/証拠金(1b)、ロスカット全決済(1c)、
  指値・逆指値(新規エントリー)とその監視・予約注文(TriggerOrder)。

## 2. ゴール / 位置づけ
- 保有建玉に対し、**利確(TP=決済指値)/ 損切り(SL=決済逆指値)**を設定し、価格条件で自動決済する。
- 1建玉に **TP と SL を各1本まで**付与できる(連動なし。OCOは段階B)。
- 対象建玉が他経路で消えたら、紐づく未発動の TP/SL を**自動失効**させる。
- 段階の位置づけ: **A(単独TP/SL・本書)**→ B(OCO・相互キャンセル)→ C(IFD/IFO)。

## 3. スコープ
### スコープ内
- 建玉への TP / SL 付与・取消・一覧
- トリガー監視 → 発動で対象建玉を**全数量決済**(利確=指定価格 / 損切り=トリガー後に現在値で約定)
- 建玉消滅(個別決済・ロスカット全決済等)時の紐づく TP/SL の**自動失効**
- PositionsTable への TP/SL 表示・操作配線

### スコープ外(後続)
- OCO(TPとSLの相互キャンセル)= 段階B
- IFD/IFO = 段階C
- **部分決済**(本系列は建玉全数量決済のみ)
- 許容スリッページ幅の指定(本系列では実装しない。将来ストリーミング注文等で導入)

## 4. 設計概要
### 4.1 決済種別と建玉サイド
決済は建玉のサイドで方向が決まる(決済側価格=LONG:Bid / SHORT:Ask)。
- **買い建て(LONG)の決済**(売って閉じる→Bid):
  - 利確 TP(上に置く): **Bid ≥ TP価格** → **TP価格で約定**。
  - 損切り SL(下に置く): **Bid ≤ SL価格** でトリガー → **現在Bidで約定**(スリッページ許容・幅指定なし)。
- **売り建て(SHORT)の決済**(買って閉じる→Ask):
  - 利確 TP(下に置く): **Ask ≤ TP価格** → **TP価格で約定**。
  - 損切り SL(上に置く): **Ask ≥ SL価格** でトリガー → **現在Askで約定**(スリッページ許容・幅指定なし)。

### 4.2 発注時の価格向き検証(不正は却下)
- LONG: TP は現在Bidより上 / SL は現在Bidより下。
- SHORT: TP は現在Askより下 / SL は現在Askより上。
- 対象建玉が OPEN であること。同種別(TP or SL)が既に付いている建玉への重複付与は却下(各1本)。

### 4.3 数量
- 決済は**対象建玉の全数量**。部分決済はしない。

### 4.4 自動失効(最重要)
- 対象建玉が OPEN でなくなったら、その建玉に紐づく**未発動の TP/SL を自動で失効**させる。
  - 経路: 個別決済(1a)、ロスカット全決済(1c)、(将来)オフセット決済。
  - 特に **ロスカット全決済(1c)処理に、決済される各建玉の TP/SL も一緒に失効させる**処理を組み込む。
- ロック内で「建玉クローズ」と「紐づく決済注文の失効」を整合的に行う(口座ロック共用)。

## 5. バックエンド仕様
### 5.1 既存調査(着手前に view して報告)
- 予約注文(TriggerOrder)の構造、指値・逆指値の監視(スケジュール)、個別決済(closePosition)、
  ロスカット全決済(1c)、建玉エンティティ、口座ロックの所在。決済注文を載せる接続点を報告。

### 5.2 enum / フィールド(additive)
- 決済注文の表現: TriggerOrder を拡張(または決済用区分を追加)。
  - `purpose { ENTRY, EXIT }`(新規/決済の軸)を追加。EXIT は対象建玉IDを持つ。
  - 種別は既存 `orderType { LIMIT, STOP }` を流用(TP=LIMIT/EXIT、SL=STOP/EXIT)。
  - `targetPositionId`、`triggerPrice`、状態。
- 状態 `TriggerStatus` に **EXPIRED(失効)** を追加(PENDING/TRIGGERED/CANCELLED/REJECTED に加える)。
- 発動由来の印(source)で TP/SL を区別できるとよい(例 source=TP / SL、または既存sourceの拡張)。

### 5.3 サービス
- 決済注文サービス: 付与(検証)/ 取消 / 一覧。建玉に TP・SL 各1本までの制約を担保。
- 監視(指値・逆指値の既存スケジュール)を拡張し、**EXIT の決済注文も評価**:
  - 条件成立 → 対象建玉を決済(利確=指定価格 / 損切り=現在値)→ 実現損益確定・残高反映(1a/1b経路)→ 建玉CLOSED。
  - 約定後、その建玉に紐づくもう一方(例 TP約定ならSL)は**自動失効**。
- 建玉クローズ系(個別決済・ロスカット全決済)に、**紐づく未発動TP/SLの失効**をフックする。
- 口座ロックで直列化・冪等。

### 5.4 API
- `POST /api/trade/positions/{id}/exit-orders`: 建玉に TP または SL を付与
  (body: type=TP|SL, triggerPrice)。向き不正・OPEN以外・重複は 4xx。
- `DELETE /api/trade/positions/{id}/exit-orders/{exitId}`(または cancel): 取消(未発動のみ)。
- `GET /api/trade/positions`(拡張): 各建玉に付与済み TP/SL(価格・状態)を含める。
- (任意)`GET /api/trade/exit-orders`: 決済注文一覧(状態フィルタ)。
- DTO返却。

### 5.5 エッジケース
| ケース | 期待挙動 |
|---|---|
| 向き不正(例 LONGのTPがBidより下) | 却下(4xx) |
| OPEN以外の建玉に付与 | 却下 |
| 同種別の重複付与(TP/SL各1本) | 却下 |
| 対象建玉が他経路でクローズ | 紐づく未発動TP/SLを自動失効(EXPIRED) |
| ロスカット全決済 | 決済される各建玉のTP/SLも失効 |
| TP約定後の同建玉のSL | 自動失効(段階Aは連動なしだが、建玉消滅に伴う失効として処理) |
| 急変で価格がトリガーを飛び越え(SL) | 現在の決済側価格で約定(スリッページ許容) |
| 同時操作(発注/決済/ロスカット/発動) | 口座ロックで直列化・冪等 |

## 6. フロントエンド仕様
- **PositionsTable** の各建玉行に:
  - TP / SL の設定操作(価格入力)。設定済みなら TP価格・SL価格と状態を表示。
  - TP / SL の個別取消。
  - 価格向きのヒント(LONGならTPは上・SLは下 等)。向き不正はエラー表示。
- 状態(待機/発動/取消/失効)を DESIGN.md の配色で色分け。
- TP/SL が発動して建玉が決済されたら、約定履歴・建玉一覧・損益・維持率に反映(既存ポーリング)。
- loading/empty/error。

## 7. この機能固有の制約
- 1建玉に **TP と SL を各1本まで**(連動なし。相互キャンセル=OCOは段階B)。
- 決済は**全数量**(部分決済なし)。
- 利確=指定価格 / 損切り=トリガー後に現在の決済側価格で約定(**スリッページ幅指定なし**)。
- 対象建玉が消えたら紐づく未発動TP/SLを**自動失効**(ロスカット全決済にもフック)。

## 8. 実装ステップ
1. 既存調査: 予約注文・監視・個別決済・ロスカット全決済・口座ロックの接続点を報告。
2. enum/フィールド追加(purpose=ENTRY/EXIT、targetPositionId、TriggerStatus に EXPIRED)。
3. 決済注文サービス(付与/取消/一覧、各1本制約、向き検証)。
4. 監視拡張: EXIT を評価し、利確=指定価格/損切り=現在値で対象建玉を全数量決済。
5. 建玉クローズ系(個別決済・ロスカット全決済)に紐づくTP/SLの自動失効をフック。
6. API(付与/取消/positions拡張)を追加。
7. テスト追加(9章)。
8. フロント: PositionsTable に TP/SL 設定・表示・取消。
9. 動作確認(10章)。

## 9. テスト（受け入れ条件）
- **TP発動(LONG)**: LONG建玉に TP=上 を付与 → Bid が TP以上 → **TP価格で**約定・建玉CLOSED。
- **SL発動(LONG)**: SL=下 を付与 → Bid が SL以下 → **現在Bidで**約定(スリッページ許容)。
- **SHORT側**: TP=下でAsk≤TP→指定価格約定 / SL=上でAsk≥SL→現在Askで約定。
- **向き不正**: LONGのTPをBidより下に → 却下。
- **各1本制約**: 同じ建玉にTPを2本 → 却下。
- **自動失効(個別決済)**: TP/SL付きの建玉を手動決済 → 紐づくTP/SLがEXPIRED。
- **自動失効(ロスカット)**: 維持率≤50%で全決済 → 各建玉のTP/SLもEXPIRED。
- **冪等/直列化**: 同時発動・決済で二重決済しない。

## 10. 動作確認手順
### バックエンド
```
# 建玉を作る(1a)
POST /api/trade/orders/market { "currencyPair":"USD/JPY","side":"BUY","quantity":10000 }

# その建玉にTPとSLを付与
POST /api/trade/positions/{positionId}/exit-orders { "type":"TP","triggerPrice":156.000 }
POST /api/trade/positions/{positionId}/exit-orders { "type":"SL","triggerPrice":154.000 }
GET  /api/trade/positions      # 建玉行にTP/SLが表示

# ニュースで上昇→TP発動(指定価格で決済)/ 下落→SL発動(現在値で決済)
POST /api/market/news/events { "currencyPair":"USD/JPY","direction":"UP","magnitudeBps":150,"durationSeconds":60 }
GET  /api/trade/positions      # TP発動で建玉CLOSED、SLは自動失効(EXPIRED)
GET  /api/trade/trades         # 決済約定が記録
```
### フロントエンド
- PositionsTable の建玉行で TP/SL を設定・表示・取消できる。
- 価格到達で自動決済され、約定履歴・損益・維持率に反映。
- 建玉を手動決済 or ロスカットで閉じると、紐づくTP/SLが失効する。
- 既存画面(監視・成行・指値/逆指値・建玉・証拠金)が壊れていない。

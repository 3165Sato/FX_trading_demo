---

あなたはプロダクトデザイナーです。学習用の架空FXデモアプリ **DemoFX** の
画面ワイヤーフレームを作ってください。最終ビジュアルより**情報設計とレイアウト**を優先しつつ、
「監視室風(オペレーションダッシュボード)」の方向性が伝わる**中忠実度のワイヤー**にしてください。

## プロダクト背景
- DemoFX は FX 取引の一般概念を学ぶための架空デモアプリ(実在サービスは再現しない)。
- 既存のレート配信・チャート・監視機能の上に、取引機能を追加していく段階。
- 実装スタックは **Next.js / React / TypeScript / Tailwind CSS / Recharts**。
  → 突飛なライブラリ前提のUIは避け、この構成で実装可能な範囲で。

## 全体方針
- **2画面構成**: ①Market Monitor(監視)/ ②Trading(取引)。上部タブ or ヘッダーで切替。
- **デスクトップ監視室風**: 高い情報密度、常時表示、ダーク系のオペレーション画面。
  - ターゲット幅は **約1440px(デスクトップ優先)**。モバイル対応は今回不要(将来検討の注記のみで可)。
- 数値は等幅(tabular)で読みやすく。価格・pips・損益などの数値表示を重視。
- 既存の機能・データに対応する(勝手に新しいデータ種別を増やさない)。

## 共通要素(両画面)
- ヘッダー/ナビ: アプリ名「DemoFX」、Monitor / Trading の切替タブ、
  フィード状態インジケータ(稼働中/停滞)、現在時刻、アクティブアラート件数バッジ。
- カラー方針(方向性として):
  - 価格の上昇=緑 / 下落=赤(レート変化・チャート)
  - 取引サイドは価格の上下色と**混同しない別系統**で(例: BUY=青系 / SELL=赤系)
  - アラート重大度: CRITICAL=赤 / WARNING=黄(amber)/ INFO=灰 or 青
- 各データ領域に **loading / error / empty** の状態を想定したワイヤーを用意。

## 画面① Market Monitor(監視)

高密度の監視ダッシュボード。以下の領域を配置:

1. **レートボード(全通貨ペア)**
   - 9ペア(USD/JPY, EUR/JPY, EUR/USD, GBP/USD, GBP/JPY, AUD/USD, AUD/JPY, USD/CHF, USD/CAD)。
   - 各: symbol / bid / ask / mid / spread(pips)/ 直近変化の上下色・矢印。
   - クリックで選択 → 下記チャート等が連動。選択中ペアを強調。
2. **メインチャート(選択ペア)**
   - bid / ask / mid の3本ラインチャート(Recharts 想定)。時間幅・件数切替。
3. **Spread監視カード(選択ペア)**
   - 現在 / 平均 / 最小 / 最大 spread(pips)。
   - ステータスバッジ: NORMAL / WIDE / VERY_WIDE / INSUFFICIENT_DATA(色分け)。
4. **ニュースパネル(疑似ニュースイベント)**
   - 直近イベント一覧: 見出し / ペア / 方向(▲UP・▼DOWN)/ 時刻 / 有効バッジ。
   - デモ用の発火コントロール(ペア選択・UP/DOWN・発火ボタン)。※学習用デモ操作と分かる見せ方。
5. **アラートパネル(異常検知)**
   - アクティブを上部に強調(severity 色)、解消済みは淡色で履歴表示、アクティブ件数表示。
   - 行: severity バッジ / 種別 / ペア / メッセージ / 時刻。
6. **Tick ログ(選択ペア)**
   - 直近 tick が流れるリスト: 時刻 / bid / ask / mid / spread。監視室らしいデータストリーム感。

レイアウトの目安(提案、調整可):
- 上部または左にレートボード、中央にチャート、右カラムに Spread / ニュース / アラート、
  下部に Tick ログ。常時見える配置を優先し、各パネルは個別スクロール可。

## 画面② Trading(取引)

注文・約定を中心に、**将来の取引パネルの枠も確保**する。

### 現行(実装済み/実装中)
1. **デモ口座サマリ(ヘッダー帯)**
   - 口座名 / 評価額 / 維持率 …は**将来枠**だが、配置場所はこの段階で確保しておく。
2. **価格リファレンス(選択ペア)**
   - bid / ask / mid / spread を大きく表示(発注判断用)。
3. **成行注文パネル**(学習の核)
   - ペア選択 / BUY・SELL / 数量(units)。
   - **BUY 側に Ask、SELL 側に Bid を明示**し、「BUY は Ask、SELL は Bid で約定」「差=Spread=コスト」が
     ひと目で分かる見せ方にする。
   - 発注ボタン、約定結果(約定価格・数量・時刻)表示。
4. **約定履歴**
   - 表: 時刻 / ペア / サイド(色分け)/ 数量 / 約定価格。
5. **注文履歴(任意)**

### 将来枠(プレースホルダとして配置・サイズ確保のみ)
6. **建玉テーブル**: ペア / サイド / 数量 / 平均建値 / 現在価格 / 評価損益。
7. **損益サマリ**: 合計評価損益 / 実現損益。
8. **証拠金・維持率**: 必要証拠金 / 維持率ゲージ / ロスカット閾値。

> 6〜8 は「Coming soon / 将来実装」と分かる形のプレースホルダでよい。
> 重要なのは、後で実装したときにレイアウトを作り直さなくて済む**場所とサイズの確保**。

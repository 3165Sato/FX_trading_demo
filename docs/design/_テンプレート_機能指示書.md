# 機能指示書テンプレート（docs/design/ 用）

> 使い方: このテンプレートをコピーして機能ごとの指示書を作る。
> 共通ルールは再掲せず、CODEX.md / DESIGN.md を参照する。ファイル名例: `YYYYMMDD_機能名.md`

---

# DemoFX 機能指示書: ＜機能名＞

## 1. 準拠
- 実装ルールは **CODEX.md** に従う(BigDecimal/HALF_UP、DTO返却、独立スケジュール、口座ロック、
  既存を壊さない・小ステップ、NEXT_PUBLIC_API_BASE_URL、logs非Git 等)。
- UIは **DESIGN.md** に従う(カラートークン、余白/角丸、情報密度、loading/empty/error、グリッド)。
- 前提機能: ＜依存する既存機能を列挙＞

## 2. ゴール / 位置づけ
- ＜この機能で何ができるようになるか＞
- ＜全体ロードマップ上の位置＞

## 3. スコープ
### スコープ内
- ＜やること＞
### スコープ外(将来 / 別チャンク)
- ＜やらないこと＞

## 4. 設計概要
- ＜中心となる考え方・モデル・判定条件・式など＞

## 5. バックエンド仕様
- 既存調査: ＜着手前に view して報告する既存エンティティ/サービス＞
- enum / フィールド(additive): ＜追加するもの＞
- サービス: ＜新規/拡張するサービスと責務＞
- API: ＜メソッド / パス / パラメータ / レスポンス / エラー＞
- 設定(application.yml): ＜キーと既定値＞
- エッジケース: ＜表で＞

## 6. フロントエンド仕様
- ＜画面/コンポーネント、配線するAPI、表示、状態＞
- ＜DESIGN.md のどのトークン/枠を使うか＞

## 7. この機能固有の制約
- ＜共通ルール以外で、この機能だけに効く注意点＞

## 8. 実装ステップ
1. 既存調査・報告
2. ＜以降、小さく刻む＞

## 9. テスト(受け入れ条件)
- ＜具体値つきの期待結果＞

## 10. 動作確認手順
- バックエンド: ＜curl例＞
- フロントエンド: ＜操作と確認＞

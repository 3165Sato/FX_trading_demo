# Issue #4 PR作成自動化 要件ドラフト

## 背景・目的

GitHub Issue #4「PRタイトル・本文の生成およびDraft PR作成を自動化する」では、Claude Codeが生成したPRタイトルと本文を一時ファイルへ保存した後、PowerShellでpushとDraft PR作成を個別に実行している現状を改善する。

現行手順には、PRタイトルの文字化けが発生し得ること、複数コマンドを毎回手動実行する必要があること、既存PRの有無によって利用者が処理を切り替える必要があること、という課題がある。

本対応の目的は、Issue番号だけを指定する1コマンドで、入力検証、現在ブランチのpush、Draft PRの新規作成または既存PRの更新、ブラウザ表示までを安全かつ再実行可能に行えるようにすることである。また、PR本文の標準項目をリポジトリ側で定義し、PRごとの記載粒度を揃える。

想定する実行形式は次のとおりである。

```powershell
.\scripts\create-pr.ps1 -IssueNumber 2
```

## 現状調査結果

### 既存構成

- リポジトリはバックエンドの `FX_trading_backend/fxdemo/`、フロントエンドの `FX_trading_front/fx-demo-front/`、設計・要件・レビュー文書の `docs/` を主な構成要素とする。
- ルートの `CODEX.md` は、小さいステップでの変更、着手前の現状調査、既存機能を壊さない最小追加を共通方針としている。
- 既存の要件文書は `docs/requirements/issue-2-requirements.md` の1件である。同文書は、背景、目的、現状仕様、変更後仕様、対象範囲、対象外、入出力、正常系、異常系、制約、テスト観点、確認済み事実、判断事項、未確定事項を明示している。本ドラフトも、事実・要件・未確定事項を分離する粒度を踏襲する。
- Gitのリモートは `origin`、GitHubリポジトリは `3165Sato/FX_trading_demo` である。ローカルで確認できたデフォルトブランチは `main`（`origin/HEAD -> origin/main`）である。
- 調査時の作業ブランチは `feature/issue-4-pr-automation` であり、Issue単位のブランチ名として `feature/issue-2-order-change` も存在する。ただし、ブランチ命名規則を定めるリポジトリ文書は存在しない。

### 既存スクリプトと一時ファイル

- リポジトリ直下に `scripts/` は存在せず、追跡済みファイルおよび全コミット履歴にもPowerShellスクリプトは存在しない。今回の `scripts/create-pr.ps1` が最初のリポジトリ共通運用スクリプトとなる。
- ローカルの `.tmp/` には、実例として `.tmp/issue-2-pr-title.txt` と `.tmp/issue-2-pr-body.md` が存在する。タイトルは1行、本文はMarkdownであり、Issue #4が示す入力命名規則と一致する。
- 既存のPR本文実例には、概要、背景、主な変更、テスト、レビュー結果、影響範囲、残課題・確認事項が含まれる。Issue #4の想定項目のうち、チェックリストと関連Issueは現行実例で標準化されていない。
- `.tmp/` はリポジトリ管理の `.gitignore` ではなく、当該作業コピー固有の `.git/info/exclude` で除外されている。したがって、別のcloneでは入力ファイルがGitの未追跡ファイルとして表示される可能性がある。

### GitHub関連設定

- `.github/` は存在しない。PRテンプレート、Issueテンプレート、GitHub Actionsワークフロー、CODEOWNERS等のGitHub関連設定は、追跡済みファイルおよび全コミット履歴に存在しない。
- PR作成・更新の既存自動化コード、および `gh pr create`、`gh pr edit`、`gh pr view` を呼び出す関連コードは存在しない。
- GitHub CLIは調査環境にインストールされていたが、既存認証トークンが無効で、実行環境のネットワーク制限もあったため、`gh issue view 4 --comments` による再取得はできなかった。
- Issue #4のタイトル、状態、作成者、本文は依頼時に提示された情報を正とする。提示情報上、IssueはOPEN、作成者は `3165Sato`、コメントは0件である。

## 要件一覧

### 機能要件

#### FR-01 PRテンプレート

- `.github/pull_request_template.md` を新規追加する。
- テンプレートには、少なくとも次の見出しをこの順序で含める。
  1. 概要
  2. 背景
  3. 主な変更
  4. テスト
  5. レビュー結果
  6. 影響範囲
  7. 残課題・確認事項
  8. チェックリスト
  9. 関連Issue
- チェックリストはGitHub Markdownのタスクリスト形式とし、最低限、変更内容の自己確認、テスト結果の記載、関連ドキュメントの更新、残課題の明記を確認できる項目を持つ。
- 関連Issue欄は、`Closes #<Issue番号>` 等のGitHubキーワードを記入できる形式とする。ただし、自動クローズの要否は本文作成者が判断する。
- テンプレートは通常のGitHub画面からPRを作成する場合の標準である。スクリプト実行時は入力本文ファイルをそのまま使用し、テンプレート内容を自動結合しない。

#### FR-02 コマンド入力

- `scripts/create-pr.ps1` を新規追加し、必須の整数パラメーター `-IssueNumber` を受け取る。
- `IssueNumber` は1以上の整数のみを許可し、未指定、0以下、整数以外の場合は処理を開始せずエラー終了する。
- スクリプトはリポジトリ内のどのカレントディレクトリから呼び出されても、Gitのリポジトリルートを基準に入力ファイルを解決する。
- 入力ファイルは次の固定規則で決定する。
  - タイトル: `.tmp/issue-<IssueNumber>-pr-title.txt`
  - 本文: `.tmp/issue-<IssueNumber>-pr-body.md`
- 任意のタイトル文字列や本文パスを直接指定する追加パラメーターは、本Issueの必須要件としない。

#### FR-03 前提ツールと認証の確認

- 外部状態を変更する前に、`git` と `gh` が実行可能であることを確認する。
- `gh auth status` 相当の確認により、対象GitHubホストへの認証が有効であることを確認する。
- ツール未導入または認証失敗時は、原因と利用者が取るべき対応を標準エラーへ表示し、push、PR作成、PR更新を行わず非0で終了する。

#### FR-04 Gitリポジトリとブランチの確認

- Gitワークツリー内で実行されていることを確認し、リポジトリ外ではエラー終了する。
- detached HEADではなく、現在のローカルブランチ名を取得できることを確認する。
- デフォルトブランチを取得し、現在ブランチがデフォルトブランチと一致する場合は、誤った直接pushおよびPR作成を防ぐためエラー終了する。
- デフォルトブランチは、まず `origin/HEAD`、次にGitHubのリポジトリ情報から判定する。いずれからも一意に取得できない場合は、`main` 等の固定値へフォールバックせず、外部状態を変更する前にエラー終了する。
- pushおよびPR操作の対象は、確認した現在ブランチとする。スクリプトがブランチを新規作成または切り替えることはしない。

#### FR-05 入力ファイルの検証と読み込み

- pushより前に、タイトルファイルと本文ファイルの両方が通常ファイルとして存在することを確認する。
- 両ファイルをUTF-8として明示的に読み込む。UTF-8 BOMの有無は問わず、PowerShellやOSの既定コードページに依存させない。
- タイトルは前後の改行を除去した1行の非空文字列として扱う。空文字、空白のみ、または複数の実質的なタイトル行を含む場合はエラー終了する。
- 本文は改行を保持した非空のMarkdown文字列として扱う。空文字または空白のみの場合はエラー終了する。
- UTF-8として正しく解釈できない入力は、文字化けしたまま処理せずエラー終了する。
- タイトルと本文の内容をシェルコマンド文字列へ埋め込まず、GitHub CLIの引数または本文ファイル指定機能を安全に利用する。Markdown中の引用符、バッククォート、`$`、日本語、複数行を内容どおり渡せること。

#### FR-06 現在ブランチのpush

- すべての事前検証に成功した後、現在ブランチを `origin` へpushする。
- `origin` が存在しない場合はエラー終了する。別名リモートの自動選択は行わない。
- upstreamが未設定の場合は、現在ブランチに対応する `origin/<branch>` をupstreamとして設定する。
- upstreamが既に設定されている場合も、意図しない別名ブランチを更新せず、現在ブランチを対象としてpushする。
- push失敗時はPRの作成・更新・ブラウザ表示へ進まず、Gitのエラーを確認できる形で非0終了する。
- スクリプトは変更のstage、commit、rebase、force pushを行わない。
- 未コミット変更が存在する場合は、push対象がコミット済みの内容だけであることを警告したうえで処理を継続する。未コミット変更の存在だけを理由にエラー終了しない。

#### FR-07 既存PRの判定

- push成功後、現在ブランチをhead、取得済みデフォルトブランチをbaseとする同一リポジトリ内のOPENなPRをGitHub CLIで検索する。
- 対象判定では、別ブランチのPRや同名ブランチを持つforkのPRを誤って選ばない。
- head、base、リポジトリ、OPEN状態がすべて一致するPRが1件の場合のみ更新対象とする。
- 一致するOPENなPRが0件の場合は新規作成へ進む。CLOSEDまたはMERGEDの過去PRは更新対象とせず、新規作成を妨げない。
- 一致するOPENなPRが複数見つかった場合は任意の1件を選ばず、PRを変更せずにエラー終了する。
- 同じheadでもbaseが異なるPRは更新対象とせず、baseを自動変更しない。

#### FR-08 Draft PRの新規作成

- 対象PRが存在しない場合、入力ファイルから読み込んだタイトルと本文を使用し、現在ブランチからデフォルトブランチへのDraft PRを作成する。
- 作成時にbaseブランチ、headブランチ、Draft指定、タイトル、本文を明示し、対話入力を要求しない。
- 新規PRへラベル、assignee、reviewer、project、milestoneを自動設定しない。
- Issue番号は入力ファイル名の選択に利用する。PR本文への関連Issue追記やIssue本文からのPR本文自動生成は、本Issueの必須要件としない。

#### FR-09 既存PRの更新

- 更新対象のPRが一意に存在する場合、入力ファイルの内容でPRタイトルと本文を更新する。
- 更新時にPRのDraft/Ready状態、base/head、reviewer、label、assignee等を変更しない。
- 既存PRがReady for reviewの場合も、Ready状態を維持してタイトルと本文だけを更新する。
- 同じ入力で再実行した場合も重複PRを作成せず、同じPRを更新対象とする。
- タイトル更新または本文更新の一部が失敗した場合は成功扱いにせず、対象PR番号と失敗内容を表示して非0終了する。

#### FR-10 結果表示とブラウザ起動

- 作成または更新に成功したPRの番号とURLを標準出力へ表示する。
- 成功したPRを `gh pr view --web` 相当の方法で既定ブラウザに開く。
- PR作成・更新が成功し、ブラウザ起動だけが失敗した場合は、PR自体が作成・更新済みであることとURLを警告として明示し、ブラウザを手動で開けるようにする。この場合、主要なPR操作は完了しているため終了コードは0とする。

#### FR-11 処理順序と副作用の抑制

- 処理順序は、パラメーター確認、ツール・認証確認、リポジトリ・ブランチ確認、入力ファイル検証、push、既存PR検索、作成または更新、ブラウザ表示とする。
- pushより前に判定可能なエラーはすべてpush前に検出し、不要な外部変更を発生させない。
- 各外部コマンドの終了コードを確認し、失敗後に後続の外部変更を継続しない。
- 成功時は新規作成か更新かを明示し、失敗時はどの段階で停止したかを明示する。

### 非機能要件

#### NFR-01 文字コード

- `.github/pull_request_template.md` と `scripts/create-pr.ps1` はUTF-8で管理する。
- 日本語、英数字、記号を含むPRタイトル・本文がGitHub上で入力ファイルと同じ内容として表示されること。
- 現行運用がWindows上のPowerShellであること、およびIssueがPowerShellの版を限定していないことから、Windows PowerShell 5.1とPowerShell 7の双方を対応対象とする。
- 両バージョンでUTF-8の既定動作が異なるため、ファイル入出力および外部コマンドへの値渡しは実行環境の既定エンコーディングに依存させない。

#### NFR-02 安全性

- デフォルトブランチからの実行、detached HEAD、認証不備、入力不足、曖昧な既存PR判定では、PR関連の外部状態を変更しない。
- タイトルや本文をPowerShell式または別シェルのコマンドとして評価しない。
- force push、既存PRのクローズ、Draft状態の変更、Issueの更新を行わない。
- 認証トークン等の秘密情報を標準出力・標準エラーへ表示しない。

#### NFR-03 冪等性

- 同じブランチ・Issue番号・入力ファイルで複数回実行しても、PRを重複作成しない。
- 再実行によりタイトル・本文を望ましい状態へ収束させる。

#### NFR-04 可観測性とエラー処理

- 利用者が、認証確認、ブランチ確認、push、PR検索、作成または更新、ブラウザ表示のどこまで進んだか判別できるログを出す。
- エラーは対象ファイル、ブランチ、PR等の文脈と修正方法が分かる日本語または明瞭なメッセージで示す。
- 必須の検証、push、PR作成または更新の失敗時は非0を返す。これらが成功した場合は、ブラウザ起動だけに失敗しても警告を表示して0を返す。

#### NFR-05 保守性

- パス解決、外部コマンド実行、エラー判定の重複を抑え、処理段階が追える構成とする。
- GitHub CLIの構造化出力（JSON等）が利用できる箇所では、人向け表示文字列の曖昧な解析を避ける。
- GitHub CLIやGitのバージョン固有挙動へ過度に依存しない。最低対応バージョンを設ける場合はスクリプト内コメントまたは関連文書に明記する。

#### NFR-06 テスト・受け入れ条件

- 少なくとも次を手動または自動テストで確認する。
  - 日本語を含むUTF-8タイトル・複数行Markdown本文でDraft PRを新規作成でき、文字化けしない。
  - 同一ブランチで再実行するとPRが増えず、タイトルと本文が更新される。
  - 既存PRがReady for reviewでも状態を維持し、タイトルと本文だけが更新される。
  - 同一head/baseのOPENなPRが複数検出された場合は、どのPRも変更せず停止する。
  - CLOSEDまたはMERGEDの過去PR、およびbaseが異なるPRを誤更新しない。
  - upstream未設定の作業ブランチをpushできる。
  - デフォルトブランチ、detached HEAD、リポジトリ外、`origin`不在、デフォルトブランチ取得不能で安全に停止する。
  - `gh` 未導入、未認証または認証無効でpush前に停止する。
  - UTF-8 BOMあり・BOMなしの入力を読み込める。
  - タイトルまたは本文ファイルの欠落、空ファイル、不正なUTF-8、不正なタイトル形式でpush前に停止する。
  - push失敗時にPR作成・更新を行わない。
  - 未コミット変更がある場合は警告し、その変更をcommitせずに処理を継続する。
  - Markdownの引用符、バッククォート、`$`、日本語、改行が欠落・展開されない。
  - 既存PR更新時にDraft/Ready状態やその他メタデータを意図せず変更しない。
  - PR操作成功後にPR番号とURLを表示し、ブラウザを開く。
  - ブラウザ起動だけが失敗した場合はURLを警告表示し、終了コード0とする。
- 文字コード関連の受け入れ確認はWindows PowerShell 5.1とPowerShell 7の双方で行う。
- 実GitHubへ接続する確認では、テスト用ブランチを使用し、デフォルトブランチや既存の無関係なPRを変更しない。

## スコープ外事項

- Claude CodeまたはCodexによるPRタイトル・本文そのものの生成。
- Issue本文・コメントを取得し、PR本文へ自動変換または自動追記する処理。
- ブランチの作成、命名、切り替え、コミット作成、stage、rebase、merge。
- force push、履歴改変、競合解消。
- PRのReady化、レビュー依頼、ラベル・assignee・project・milestoneの設定。
- CI結果の待機、失敗解析、マージ、自動リリース。
- 既存PRのクローズ、再オープン、Issueの更新またはクローズ。
- GitHub ActionsによるPR作成自動化。
- バックエンドまたはフロントエンドのアプリケーション機能変更。
- `.tmp/` のGit除外方法の変更。共有除外が必要な場合は別Issueで扱う。

## AI判断で確定した事項

### Windows PowerShell 5.1とPowerShell 7を対応対象とする

- 決定: 両バージョンで動作することを受け入れ条件とする。
- 根拠: IssueはWindows上のPowerShell運用を前提とする一方で版を限定していない。どちらか一方へ限定すると既存運用環境を不必要に狭めるため、互換性を優先する。

### UTF-8 BOMあり・BOMなしを受け付ける

- 決定: 入力ファイルはUTF-8 BOMの有無を問わず受け付け、不正なUTF-8は拒否する。
- 根拠: BOM差は内容上の差ではなく、Windows PowerShell 5.1とPowerShell 7の生成ファイルに互換性を持たせることが文字化け防止と既存運用維持に適する。

### デフォルトブランチを推測しない

- 決定: `origin/HEAD` とGitHubリポジトリ情報から取得できない場合はエラー終了し、`main` 等へフォールバックしない。
- 根拠: リポジトリごとに既定ブランチ名は異なり得る。推測による誤push・誤PR作成を避ける安全側の処理であり、現行リポジトリでは `origin/HEAD` から `main` を取得できる。

### 更新対象を同一リポジトリ・同一head/baseのOPENなPRに限定する

- 決定: 条件に一致するOPENなPRが1件の場合だけ更新する。CLOSED/MERGEDの過去PRとbase違いのPRは更新せず、一致するOPENなPRがなければ新規Draft PRを作成する。複数一致時は停止する。
- 根拠: 現在進行中の同一変更だけを冪等に更新でき、過去PRや別の統合先を誤更新しない。複数一致時の自動選択には安全な根拠がないため、PRを変更する前に停止する。

### 既存PRのレビュー準備状態を維持する

- 決定: 既存PRがDraftでもReady for reviewでも、タイトルと本文のみ更新し状態を変更しない。
- 根拠: Issueが求める更新範囲はタイトルと本文であり、Ready状態の変更はレビュー運用への不要な副作用となる。

### ブラウザ起動失敗は警告扱いとする

- 決定: PR作成・更新の成功後、ブラウザ起動だけに失敗した場合はURLを警告表示して終了コード0とする。
- 根拠: 主要な外部状態変更は完了しており、URLから手動で継続できる。非0にすると自動実行側がPR操作自体の失敗と誤認するためである。

### 未コミット変更は警告して処理を継続する

- 決定: 作業ツリーがdirtyでも停止せず、未コミット変更はpushされない旨を警告する。
- 根拠: `git push` の対象はコミットであり、スクリプトはstageやcommitを行わない。停止は既存の手作業フローを不必要に制限する。

### リモート名は `origin` に固定する

- 決定: 初期実装は現在のリポジトリ構成に合わせて `origin` を使用し、不在時は停止する。
- 根拠: 実在するリモートは `origin` であり、別名リモートの探索・選択はIssueの範囲を超える。固定する方が処理対象も明確になる。

### `.tmp/` の共有除外は本Issueで変更しない

- 決定: `.gitignore` 等は変更せず、必要なら別Issueで扱う。
